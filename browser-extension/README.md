# 拾签 Tagrove · Chrome / Edge 网页采集 v0.6.13

日期：2026-10-19。配套桌面 v0.6.13，开发者模式手动加载；扩展界面为中文。

默认采用群青主题，与桌面端的新用户默认主题一致。

本轮功能保持兼容，工具栏、扩展管理页、采集弹窗和采集队列使用去除白色背景和底板后的透明 Tagrove Logo。要显示新图标，请在原扩展目录替换本轮文件后点击“重新加载”；无需卸载扩展，扩展 ID 与已有队列保持兼容。

英文安装与使用步骤见 [双语项目说明](../README.md#chrome-插件--chrome-extension)。插件界面目前为中文。

## Microsoft Edge 安装与连接

1. 使用本轮 `Shiqian-v0.6.13-Edge-extension.zip`，解压到固定文件夹。
2. Edge 地址栏打开 `edge://extensions`，启用“开发人员模式”，点击“加载解压缩的扩展”，选择含 `manifest.json` 的目录。
3. 固定拾签到 Edge 工具栏，运行配套 v0.6.13 桌面程序。
4. 桌面“偏好设置 → 浏览器采集”选择 **Microsoft Edge**，点击“连接 Edge 扩展”。不要选择 Chrome 来替代 Edge 的独立连接设置。
5. 在普通 HTTP / HTTPS 网页中打开拾签弹窗，检查显示已连接 v0.6.13。网页右键也可采集链接、文字或图片。
6. 升级时覆盖原 Edge 扩展目录并“重新加载”；桌面 EXE 移动后选择 Edge 修复连接，不卸载扩展或清空待处理队列。

Edge 与 Chrome 使用同一套采集代码与固定公钥，因此开发者模式的扩展 ID 相同；两者的浏览器存储互相隔离，队列、草稿、已选标签不会跨浏览器自动同步。移除 Edge 本机连接会保留 Chrome 连接与共享配置；“暂停全部浏览器采集”作用于两者。

Microsoft Edge: unpack the Edge ZIP, open `edge://extensions`, enable Developer mode, choose Load unpacked, and select the manifest folder. In desktop 0.6.13, choose Microsoft Edge under Preferences → Browser capture, then connect. Reload the existing folder to upgrade. Each browser has independent drafts and queues; removing one browser connection retains the other. Pause applies to both.

当前为本地开发交付，不代表已提交 Microsoft Edge Add-ons 审核。商店将来分配不同扩展 ID 时，需经过明确配对后再加入来源白名单；本轮不放宽为通配来源。

## Chrome 安装或升级

1. 在旧桌面导出标注备份，重要原件另行备份。退出旧实例，再运行 v0.6.13 EXE 或安装包。
2. 将扩展 ZIP 解压到固定目录。Chrome 打开 chrome://extensions，开启开发者模式，加载包含 manifest.json 的文件夹。
3. 已装旧扩展：在原目录替换文件后点“重新加载”，核对版本 0.6.13。保留原 Chrome 配置和扩展数据，不要卸载或清除队列。
4. 桌面偏好设置 → 浏览器采集 → 选择 Google Chrome → 连接 Chrome 扩展。移动 EXE 后修复连接。桌面需运行；不自动启动桌面。
5. 打开 HTTP／HTTPS 网页，检查扩展显示已连接本机拾签 v0.6.13。

## 采集与选标签

右键采集在所用浏览器右上角插件弹窗打开，不新开页面；当前浏览器支持 action.openPopup 时可直接唤起，失败时保留草稿并提示点击拾签图标。建议固定到工具栏。弹窗内容采用大圆角，外框由浏览器控制。工具栏保存网页，或右键保存链接、文字摘录、图片；检查草稿后点击保存才入库。标签区搜索并多选已有普通标签，最多 50 个。文件夹标签、未确认 AI 标签不在列表中；搜索最多返回 500 项，可输入关键词缩小范围。标签有本地缓存，离线仍可选择和暂存。重命名后刷新目录，已删除的标签需在队列重新编辑。

网页正文尽力读取可见 main／article／body 文本，最多 12,000 字符；权限受限时只保留标题来源。摘录最多 20,000 字符。正文摘要不是整页离线归档，不采集密码或表单输入值。图片支持公开 HTTP／HTTPS PNG、JPEG、WebP、GIF、BMP，50 MiB、1 亿像素；GIF 预览为首帧。下载不带 Chrome 登录、Cookie、授权或代理；403 兼容重试仅发送来源站点 Referer，不支持登录图片、私网、SVG、blob/data 和整站抓取。

未选标签且启用桌面 AI 自动标注后，新采集的链接／摘录／图片自动排队，内容发送到所配置服务，可能计费。手动标签保留；AI 建议在桌面确认后才进入普通标签池。停用 AI 时只保存。重复资料可补充手动标签，但不重复识别。

## 队列与排障

离线、网络或写入失败会保留任务，恢复后重试；只有桌面确认才算完成。队列最多 200 项，不淘汰未完成项；独立草稿最多 20 项、保留 24 小时。相同请求 ID 重试防止重复保存。队列“重新编辑”可修改未完成任务的标签与内容，用新 ID 替换旧任务。临时图片地址可能过期，永久格式错误不持续重试。

所选标签被删除：刷新并重新编辑。协议／能力不匹配：升级两端到 0.6.13。桌面离线：运行程序并修复连接。401/403/404 图片：核对公开地址，受限图片先本地保存。不要为排障清空扩展数据。

桌面网页资料 → 内容，详情或放大预览默认在线加载来源；可切换阅读副本。独立 WebView2 不共享 Chrome 登录；网页不能调用本地 API，不开放下载或新窗口。普通本地 HTML 沿用静态／源码预览。

数据库 schema 7；图片资料包格式 7，阅读副本格式 6。跨电脑使用资料包，标注备份不含原件。断开连接不删资料或队列；移除本机连接只清理当前库拥有的注册，安装器卸载自动清理仍待实现。

已选标签的采集只保存并添加标签，不自动识别；桌面 0.6.13 实现此规则，扩展界面同步提示。文件夹标签不发送到 AI 候选池，模型返回的文件夹建议会被忽略。

## 保存失败与诊断（v0.6.13）

保存失败时，扩展弹窗和采集队列显示失败环节、错误代码、经过脱敏的具体原因和处理建议。图片服务器返回 HTTP 状态时，保留状态码：例如 403 为拒绝访问，404 为资源不存在，429 为访问频率限制；DNS 解析失败、下载超时、格式错误、图片超限、标签失效、连接异常和本地写入失败分别显示。

“已暂存到浏览器队列”只表示浏览器保留了任务，尚未确认保存到桌面。内容校验失败或浏览器队列写入失败时，应保留当前输入，按提示修正后再提交。临时错误仍按原规则自动重试；地址、格式、标签等需要人工处理的问题，在队列中使用“重新编辑”。不会因为诊断而自动清空任务。

点击“技术详情（已脱敏）”可查看错误时间、请求 ID、采集类型、尝试次数、本次耗时、扩展版本、已获取的桌面版本及来源站点。桌面版本无法获取时明确显示“尚未获取”。点击“复制诊断报告”，将报告连同复现步骤发给开发者即可；建议同时说明当时保存网页、摘录还是图片，以及能否在浏览器直接打开原图。

报告不附带网页正文、标题、完整链接及本机路径，并对常见凭据字段脱敏；分享前仍应检查剩余内容。诊断保存在本机浏览器队列，不自动上传。旧失败记录如果没有底层原因，会注明“旧记录未保留底层原因”，重试后更新诊断；成功后清除本项旧错误。浏览器或桌面未提供的信息不会凭空补造。

## 图片服务器返回 403 时（v0.6.13）

403 表示服务器拒绝此次访问；仅凭状态码不能确定是否需要登录，也不能保证更换请求头后就能下载。新版先按原方式请求；遇到 403 且可以安全发送来源时，增加一次来源站点兼容重试。Referer 只包含来源站点，不包含页面路径、查询参数或片段；HTTPS 来源不向 HTTP 图片发送来源信息。所有图片目标和重定向继续检查公网地址，下载不携带 Chrome Cookie、登录信息或授权字段。

如果兼容重试仍失败：

1. 在扩展打开“采集队列”，找到失败的图片任务，点击“打开来源网页”。
2. 在浏览器使用网站提供的下载入口，或将对应图片另存到本机。需要登录的网站请在浏览器正常完成登录；拾签不读取登录凭据。
3. 回到采集队列，点击“选择已下载原图”。拾签会打开本机文件选择窗口，请选择对应图片。
4. 拾签校验实际图片内容、格式、体积和尺寸后入库，保留这条任务的网页来源、原图片地址、标题和标签。选择的原文件保持原样，资料库保存副本。

支持 PNG、JPEG、WebP、GIF、BMP，不超过 50 MiB、1 亿像素。请自行确认选择的文件对应此网页图片；软件不宣称能验证它与被拒绝的远端原图完全一致。取消选择不删除任务；选错格式或文件不可读会显示原因，可以再次选择。窗口打开期间工作台及连接服务仍可响应，队列自动查询结果；关闭队列后可重新打开继续查询。重试成功清除旧错误，使用同一请求标识避免重复入库。桌面重启后，如果资料已入库，可从回执恢复成功状态。

本轮需要桌面端与扩展均更新为 v0.6.13。未增加 Chrome 网站访问、Cookie 或下载权限。使用新 EXE 路径后在桌面偏好设置修复浏览器连接；原扩展目录覆盖并重新加载，保留旧队列。已有 403 任务也可直接使用原图补救，无需删除重建。若想重新尝试新版网络下载，可在“重新编辑”中核对地址后保存。
