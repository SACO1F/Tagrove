# 拾签后续开发计划：Beta.12 → 稳定版 → 预览、整理与协同

更新日期：2026-10-11。当前基线：桌面端 v0.3.0-beta.12 预发布候选。后续版本号为建议，尚未交付；按验收结果推进，不承诺固定发布日期。

## 1. 当前阶段

拾签已完成本地资料整理的主要闭环：导入、标注、检索、预览、批量处理、导出和备份。近期修复集中在选择、标签候选、浮窗同步、布局与窗口交互。下一阶段优先把开发电脑上的可用性推进到同事电脑上的可靠安装、升级与持续使用，再增加整理效率和外部协同。

| 模块 | 当前能力 | 待推进 |
| --- | --- | --- |

| 标签 | 普通／文件夹分组、重命名同步、批量添加、删除及候选去重 | 合并、排序、智能集合 |
| 标签浮窗 | 拖拽入口、九点编辑、颜色、置顶、尺寸与位置保存、最近三步记录 | 跨窗口拖拽、多屏恢复与休眠唤醒 |
| AI 标注 | 已有标签复用、待确认建议、接受／拒绝与浮窗同步；手工标注导入跳过 AI | 批量审核、质量评测、处理范围和费用控制 |

- alpha.10 → Beta.9 兼容验证（历史资料，见 v0.6.12 源码快照）：实际 EXE 依次使用合成资料库，标签、备注、收藏、部分偏好和旧备份恢复通过；没有覆盖另一台电脑上的安装器升级、所有偏好或 AI 密钥。

## 2. 第一优先级：v0.3 候选收尾（当前 Beta.12）

冻结新增大型功能，集中验证安装、数据、原生交互和交接。没有发现代码缺陷时，不必为了版本号额外修改产品。

| 优先级 | 工作项 | 验收条件 |
| --- | --- | --- |
| P0 | 干净 Windows 11 x64 安装 | 覆盖 WebView2 已安装／缺失环境，首次启动、快捷方式、工作台和浮窗正常；记录系统和安装方式 |
| P0 | alpha.10 实际覆盖升级 | 在隔离用户或测试电脑运行安装器，核对记录数、标签、备注、收藏、偏好、备份；既有资料不被覆盖 |
| P0 | 卸载与重装边界 | 合成资料验证数据保留和重装后可用，说明保留／清除的实际行为；不用真实用户资料做删除测试 |
| P0 | 标题栏实机操作 | 物理鼠标拖动、双击、八方向缩放、最大化／还原、Windows 吸附、Alt+F4；保存与退出流程正常 |
| P0 | 浮窗与跨窗口拖拽 | 桌面、资源管理器、工作台；100%／125%／150% 缩放、双屏、断屏、休眠唤醒；目标命中准确，窗口可找回 |
| P0 | 同事实机交接 | 另一台电脑导入资料包，核对数量、内容校验、标签、备注和收藏；中文长路径、不同盘符、外接盘离线有明确结果 |
| P0 | 恢复与异常处理 | 旧／新备份、损坏包、权限不足、空间不足、取消与异常退出；失败结果不冒充完整结果，既有记录可恢复 |
| P1 | 全天运行 | 至少一次 8 小时代表性工作日，记录内存、预览缓存、任务和唤醒后的响应，定位持续增长 |
| P1 | 发布重复性 | 统一版本、构建、回归、源码快照和 SHA-256 校验，形成可复用清单与证据 |

稳定版门槛：P0 完成，没有未解决的数据丢失／损坏、无法启动／升级或核心流程阻断；备份恢复和同事实机交接有可复现证据。全天运行发现异常时继续候选迭代。

开发者可先完成脚本与合成检查；物理鼠标、多屏、干净系统和同事电脑依赖相应真实环境。没有条件执行的项目标记“待验证”，不以模拟结果替代。

## 4. v0.4：长期整理效率

### 4.1 标签治理与智能集合

- 标签合并：预览源／目标标签和受影响文件，消除重复关联并保留来源语义；结果完整、失败可恢复。重命名已存在，不重复列为新功能。
- 常用标签排序：浮窗排序、搜索和键盘定位；文件夹标签继续排除在可添加的浮窗标签池之外。
- 智能集合：先保存标签、类型、状态、时间等查询条件，新资料自动进入匹配集合；首版依赖现有元数据查询。

### 4.2 路径与资料交接

- 批量路径映射：换盘符或根目录时，先展示命中、缺失、冲突和修改数量，再确认提交；失败不部分覆盖记录。
- 选定目录监听：用户启用后跟踪可确认的移动／改名；临时离线与真正缺失分开提示，不因离线删除标注，不仅靠相同文件名认定身份。
- 重复资料策略：明确相同内容、相同路径和不同备注的处理，先提供可审阅冲突结果，再考虑自动合并。

### 4.3 规模与持续操作

- 用 1 万／5 万条代表性资料测量启动、搜索筛选、滚动、PDF 预览和导出；记录硬件、数据组成及冷／热缓存差别。
- 设置缩略图和预览缓存边界，检查长时间使用及批量导入的内存曲线，优先修复实测瓶颈。
- 引入持久操作记录，为重启后追踪、精确回退和 Agent 写操作打基础；现有工作台撤销不等于完整持久审计。

### 4.4 常见文件预览（2026-10-11 纳入）

需求：卡片便于辨认内容，详情/放大预览便于阅读 PDF、Word、Excel；保留轻量安装包。方案依据见文件预览研究（历史资料，见 v0.6.12 源码快照）。该专项尚未实现，不挤占 v0.3 稳定版 P0 验收。

| 顺序 | 工作项 | 验收条件 |
| --- | --- | --- |
| 1 | PDF 总页数、翻页、缩放、按需渲染 | 复用已有 PDF.js；中文/扫描件/复杂图片可读；切换文件释放任务和 Canvas；损坏、加密、超限文件明确降级 |
| 2 | DOCX 卡片摘要与只读阅读 | 优先内嵌缩略图，缺失时首段摘要；完整阅读按需加载；不改写原文件，复杂分页说明边界，禁止外链与宏执行 |
| 3 | XLSX/CSV 工作表阅读 | 卡片仅首表少量行；切表、表头、虚拟滚动；优先已保存的单元格结果，未计算结果不冒充已计算；不执行宏 |
| 4 | 体积/性能专项 | 同工具链 A/B 构建；Word/Excel 首期安装器增量目标 ≤2 MiB；固定机器/样本记录冷预览、缓存命中、峰值内存与磁盘缓存 |
| 5 | 旧格式与高保真可选增强 | 单独验证 XLS；DOC/PPT 无能力时默认程序打开；系统处理器/外部转换器按需启用，不强依赖同事安装 Office |

建议初期性能目标：普通 1–5 MiB 文件冷预览 2 秒内、已缓存卡片 100 ms 内；这是待验证目标，不是当前性能承诺。解析限制解压量、条目数、单项大小、耗时与并发，重型 Office 初期并发 1；基础包不携带整套办公引擎。

实测 docx-preview + JSZip 两份 min.js 约 169 KiB，但不等于最终安装器增量。动态加载只减少启动成本，不减少总安装包。最终验收必须用集成构建测量；SheetJS 体积尚无本次可核验数据，不提前承诺。

## 5. AI 标注：质量与人工审核

1. 建立 30～50 份人工确认的图片／文档样本，记录标签复用、新建议采纳、错误建议、耗时和实际成本；使用合成或明确允许测试的资料。
2. 增加批量审核：接受、修改、忽略及来源展示；未确认建议不进入手工标签池，用户已确认决定予以保留。
3. 减少重复和近义建议；合并只提出可审阅结果，不自动改动手工、文件夹或已接受标签。
4. 完善取消、重试、请求去重、处理范围和预算上限，避免重复添加或重复消耗。
5. OCR／文档内容索引作为后续可选能力，先说明读取和外发范围再评测，不把增加模型调用等同于体验升级。

## 6. 浏览器扩展与 Agent

共同前置：抽取统一查询／标注业务服务，定义请求版本、授权范围、来源、请求 ID 和错误语义。扩展与 Agent 不直接修改 SQLite。新增网页／摘录类型前，先确定数据迁移、备份格式和旧客户端兼容边界。

浏览器首版建议作为 v0.5 候选：先保存链接、标题、来源和选中文本，再加入主动选中的图片；桌面共享标签检索，区分链接与本地副本。桥接需要授权和版本握手，断线重试不重复。验收完整的“浏览器保存 → 桌面找回 → 备份／交接恢复”流程。参考 浏览器设计（历史资料，见 v0.6.12 源码快照），其中版本号是文档版本，不代表扩展已交付。

Agent 可在查询服务稳定后独立原型，不必等浏览器全部完成。第一阶段只读检索、标签列表、元数据查询，自然语言转成可解释条件，返回真实结果和定位入口，限定授权范围。

第二阶段才提供批量标注、合并和导出：先生成计划，经用户审阅再提交；要求幂等、冲突检测、持久记录与精确回退。撤回自己的变更不能覆盖用户后续编辑。参考 Agent 分析（历史资料，见 v0.6.12 源码快照），历史进度描述不作为当前完成状态。

| 下一轮 | v0.3 候选稳定验收（当前 Beta.12） | 验收矩阵、复现脚本、必要修复与候选包 | 实际安装、多屏和同事环境 |
