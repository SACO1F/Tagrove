# 拾签 v0.4.7：大资料库优化

2026-10-12。本轮为本地开发交付；公开 GitHub 下载仍为 RC.4，未上传。

## 改进

- 目录监听先通过父目录索引缩小关联记录范围，再核对路径组件、递归和忽略规则。含 Unicode 大小写变体的根目录保留完整核对，避免漏记录；原有 8 个目录／每目录 20,000 条目限制不变。
- 文件分页批量读取标签，合并 AI 状态查询，减少逐个文件查询。标签筛选优先利用标签关联索引；增加文件大小、目录及统计用索引。每页仍最多 100 条，保持现有虚拟滚动和排序语义。
- 文件状态检查仅在内容或状态发生变化时写入。合并界面刷新通知，检查期间分批让出执行时间；重复点击刷新不再启动多个检查线程，退出时停止后续检查。
- 已完成预览的编码数据使用 24 MiB、最多 300 项的内存缓存，按最近使用淘汰；完成的 Promise 不再重复持有预览数据。仍保持最多 3 个并行预览任务。
- 磁盘缓存分级：图片／PDF 缩略图预算 384 MiB，Office 卡片摘要预算 128 MiB，各最多 10,000 项。启动及约每分钟检查，繁忙的导入、交接、路径修复期间暂缓；超预算时按生成时间清理较旧项目。偏好设置保留手动清理入口。

这些预算管理可再生成的预览缓存，不包含原文件、标签、备注、收藏、备份或 WebView 解码纹理。磁盘维护为周期检查，检查间隔内可能暂时超预算；不是整个程序内存的上限。缓存清理只处理已知命名的生成文件，不遍历子目录或链接。

## 测量与兼容

建立固定 1 万／5 万条中文文本元数据基准，直接调用生产 Store 查询和目录关联逻辑，比较同一开发测试编译配置。5 万条记录的热查询 P50：首屏 14.79 → 8.61 ms，标签筛选 72.65 → 16.13 ms，资料库统计 1299.04 → 707.39 ms；仅关联 100 条记录的目录查询 3338.48 → 6.74 ms。深分页未获得改善，全文片段搜索仍随记录数增长。

这些数字不是发布版冷启动、真实 5 万份文档解析或多台机器成绩；详细条件和局限见 性能报告（历史资料，见 v0.6.12 源码快照）。另以 50,000 条合成元数据及 128 张真实合成图片验证发布版分页、预览、虚拟布局及设置入口。

没有新增运行时依赖。数据库格式仍为 v2，新增索引可再生成；恢复旧备份后补建索引。升级前导出标注备份，退出工作台及浮窗，安装时保留应用数据。
