## 如何填写

在测试电脑上安装候选包，先用合成文件创建测试库，记录 Windows 构建号、WebView2、版本、显示器/缩放、运行介质、测试者和日期。每项记录操作、预期、实际结果与问题；证据整理到项目 docs/evidence 下，避免上传真实资料、路径、密钥或未脱敏诊断。

确认某项确实通过后，将源码中 `docs/stable-acceptance.toml` 对应项改为 passed，填写 tester/date/environment/result 和证据文件路径。长期使用项填写实际 duration_hours。发现阻断问题时将 unresolved_blockers 填为实际数量。填写零不代表已完成全部验收。

运行 `python scripts/stable-release-gate.py` 检查记录结构、项目完整性、证据文件、八小时门槛与阻断问题。该脚本无法判断证据内容是否真实，需要人工复核。

## 正式版本提交顺序

1. 关闭并回归全部数据丢失/损坏、启动/升级或核心流程阻断问题。
2. 完成上述实机记录并人工复核，正式发布检查通过。
3. 将六处版本统一为 0.3.0，准备正式指南和验证记录，重新构建，不将 rc.1 程序直接改名当正式版。
4. 在最终 0.3.0 程序上复核核心操作、升级和恢复，核对源码、二进制、Git 标签及 SHA256。
5. 经正式交付确认后发布。候选可以供小范围验收，不能标为正式稳定版。
