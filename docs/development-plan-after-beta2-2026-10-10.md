# 拾签后续开发计划

更新日期：2026-10-10  
基线：桌面端 v0.3.0-beta.2，本地交付已完成。后续版本为建议里程碑，尚未实现；根据验收结果排期，不作为发布日期承诺。

## 1. 开发方向与顺序

先完成稳定交付，再提高资料维护与查找效率，随后扩展采集和智能整理。

**推荐顺序：v0.3 稳定验收 → v0.4 标签治理与文件重新关联 → AI 批量审核 → 浏览器采集 → Agent 只读查询 → Agent 受控整理。**

浏览器与 Agent 共用业务服务。只读 Agent 原型不必等待浏览器全部完成，但稳定版验收期间应集中修复已有问题。保持绿色主题、简洁界面和浮窗操作习惯，动效用于状态反馈、目标定位和操作连续性。

## 2. 当前进度

| 模块 | 已有能力 | 剩余重点 |
| --- | --- | --- |

| AI 标注 | 复用标签、新建议接受／拒绝、未确认隔离、失败重试 | 集中审核、质量评测、调用预算 |

已验证：核心回归 88 项通过、2 项忽略；最终发布程序 1 GB 合成资料包流程与重启通过；Beta.1 数据升级与旧备份恢复通过；600 秒持续操作、3308 次备注保存／查询循环通过。

上述结果不能替代干净系统安装、安装器覆盖升级、跨设备与全天使用验收。现有记录在项目 `docs/validation-v0.3-beta2.md`。

## 3. 阶段一：v0.3 稳定交付（P0）

### 3.1 安装、升级与同事交接

1. 在干净 Windows 用户或测试电脑验证安装、首次启动与导入，覆盖已安装和未安装 WebView2 两种环境。
2. 验证安装器从 Beta.1 升级到 Beta.2：备份并退出工作台和浮窗，再安装；核对文件、标签、备注、收藏与设置。
3. 在测试用户下验证卸载、重新安装的数据保留行为，令指南、提示与实际行为一致。
4. 由 2～3 位同事按说明独立安装并导入 `.sqtagpack`，记录步骤、结果与诊断报告。此项需要实际试用者，不自动发送资料。

**验收标准**：目标环境安装、启动、升级、备份与交接可复现；没有原文件或标注损失；每位试用者能完成交接，失败有明确原因和恢复步骤。

### 3.2 原生交互与持续运行

- 双屏 100%／125%／150% 缩放：跨屏移动、标签拖向工作台及资源管理器、浮窗置顶与缩放。
- 改变主屏、拔除显示器、重启后，浮窗能回到可见区域。
- 连续使用一个工作日，观察内存、预览缓存、取消任务、睡眠唤醒、移动盘断开重连。
- 在可恢复测试环境验证权限拒绝、磁盘满、损坏资料包和中断恢复；正式用户库与原文件不作为破坏性测试材料。

**验收标准**：窗口与拖拽坐标正确，恢复结果可核对；数据损坏或丢失、无法安装启动等问题关闭后，再考虑稳定版。

### 3.3 发布与支持

- 明确 Windows／WebView2 支持范围。
- 固定核心测试、前端构建、桌面流程、安装验证与校验清单的发布步骤。
- 核对版本号、README、更新记录、安装包、源码快照与诊断信息。
- 实机验收通过后安排 GitHub 发布；代码签名与自动更新独立评估。

**交付物**：问题／环境矩阵、实机验收记录、稳定版安装包、源码快照、指南、版本说明和 SHA-256 清单。已有检查表：`docs/beta2-real-device-checklist.md`。

## 4. 阶段二：v0.4 标签治理与资料维护（P1）

### 4.1 标签合并与常用标签管理

场景：出现“参考”“参考素材”等近义标签，希望合并而不丢失关联。

- 选择源标签和目标标签，预览文件数量、重复关联与浮窗预设影响。
- 用事务合并；明确颜色、排序与预设引用规则，保留备注、收藏及其他标签。
- 普通标签、文件夹标签与 AI 待确认建议保持来源区别，不静默互相转换。
- 结果可检查，撤回有明确边界；后续修改产生冲突时提示用户。
- 增加标签搜索、排序与常用选择；浮窗候选仍排除文件夹及未确认 AI 标签。

**验收标准**：无重复关联与悬空引用；侧栏、详情、统计和浮窗一致；失败、取消不部分落库。

### 4.2 文件失联与重新关联

场景：移动文件夹后，资料仍有标注，但旧路径失效。

- 在“需要关注”集中显示原因，支持定位新文件或映射旧目录到新目录。
- 先生成候选，再核对身份、内容或用户确认；同名文件不直接替换。
- 文件夹来源标签变更与手工标签分开，预览保留、修改和无法确认项。
- 目录监听先作为提示，收到变动后再校验，不把事件直接当作文件身份依据。

**验收标准**：关联后记录身份、备注、标签和收藏保留；歧义提示；映射不覆盖正确记录；移动盘离线不会触发资料删除。

### 4.3 规则集合与性能

- 将组合筛选保存为集合，例如“参考素材＋图片＋最近 30 天”；集合保存查询规则，不复制文件。
- 建立 1,000／10,000 文件的合成基线，测首次显示、滚动、搜索和预览的 P50／P95 耗时与内存。
- 根据测量优化查询、缩略图调度、缓存容量与失效，生成和扫描支持取消。

**迭代拆分**：先标签合并，再重新关联，最后集合与性能。每轮独立测试、文档和打包，避免一次迁移多个高风险模块。

## 5. 阶段三：AI 批量审核与质量提升（P1）

先解决建议是否准确、审核是否省事，再提高自动化程度。

1. 建立 30～50 份人工确认的图片／文档样本，覆盖常用类别与难分类内容。
2. 增加集中审核视图，逐文件展示建议、理由与来源，可接受、修改、拒绝；批量接受前预览范围。
3. 优先复用标签，新建议单独显示；未确认建议不进入可添加标签池，手工标注入口导入继续跳过识别。
4. 限制批量数量、并发、重试次数与预算；缓存绑定内容版本和模型配置，更新后失效。
5. 记录复用率、新标签合理性、采纳率、误标率、P95 耗时与实际成本；模型自报置信度不作为准确率。

**验收标准**：确认后文件、标签池和浮窗候选同步；拒绝不残留孤立候选；重复确认不重复创建；失败和取消不覆盖手工修改；效果相比基线有明确改善。

OCR、全文与语义检索单独立项，先定义提取内容、索引容量、权限、失效和备份边界，再选择实现。

## 6. 阶段四：浏览器插件首版（P2）

先做完整而有限的“网页资料进入拾签”流程。

**前置工作**：抽取共用业务服务；定义本地文件、网页链接、摘录、托管图片的数据模型；区分身份、来源和本地副本；完成迁移、保护备份、旧客户端兼容和资料包格式方案。

**首版范围**：

- 保存当前网页链接、标题、时间及选定标签。
- 保存选中文本、单张用户选定图片，保留来源页面。
- 桌面未启动时进入可查看的待同步队列，连接后幂等提交，失败原因可见。
- 支持 Chrome／Edge；桥接安装、连接状态与卸载步骤进入指南。

全站抓取、整页离线镜像、云同步和多人协同不纳入首版。

**验收标准**：离线重试不重复；失败可恢复；资料可回溯来源；迁移前后桌面与资料包正常；安装卸载可复现。基础设计：`docs/browser-extension-design-v0.2.md`。

## 7. 阶段五：Agent 查询与受控整理（P2）

### 7.1 只读查询

通过共用服务暴露搜索、标签列表和文件元数据，候选工具为 `search_files`、`list_tags`、`get_file_metadata`；名称与协议在实现时确认。

- 用户选择查询范围；默认元数据，正文与图片读取另行授权。
- 自然语言转为现有过滤条件，结果可定位到工作台并解释匹配依据。
- 分页与数量上限明确；外部适配器失败不影响桌面。
- 外部客户端不直接写 SQLite，不提供任意路径、SQL、Shell 或原文件删除工具。

**验收标准**：30～50 条检索意图有人工结果与相关性记录；越界拒绝；只读工具不修改业务资料；用户理解数据交给哪个客户端。

### 7.2 受控整理

流程：“选中文件 → 建议计划 → 用户预览与修改 → 确认 → 提交 → 查看结果与撤回”。

- 计划绑定文件／标签版本、范围、摘要及有效期。
- 请求幂等，执行日志持久保存；并发修改冲突时重新审核。
- 撤回仅作用于该次操作，保留之后的用户修改，不使用全局撤销代替。
- 文件、网页和备注中的指令视为资料内容，不改变工具权限。

**验收标准**：重复请求不重复写；重启可追踪；冲突不覆盖；撤回准确；模型失败不留下半成品批次。目标设计：`docs/agent-integration.md`。

## 8. 建议迭代节奏

按工作包推进，不承诺固定周数；达到当前轮退出条件后再进入下一轮。

| 迭代 | 重点 | 退出条件 |
| --- | --- | --- |
| 下一轮：Beta.3 或稳定候选 | 安装升级、同事交接、浮窗修复 | P0 缺口有记录并关闭，交付可重复 |
| v0.4 第一轮 | 标签合并与常用管理 | 关联、统计与预设同步，撤回边界通过 |
| v0.4 第二轮 | 文件重新关联 | 映射预览、身份核对与冲突提示通过 |
| v0.4 第三轮 | 规则集合、大图库优化 | 有前后测量数据，集合重启复用 |
| AI 体验轮 | 集中审核、评测与预算 | 有质量基线，确认／拒绝一致 |
| 浏览器首版 | 链接、摘录、单图采集 | 安装、队列、来源与迁移通过 |
| Agent 原型 | 自然语言只读查询 | 授权、相关性与客户端兼容通过 |
| Agent 整理版 | 计划确认、幂等、精确撤回 | 冲突、追踪、重试与撤回通过 |

每轮聚焦一个主要用户目标。临时生成物用固定缓存／QA 目录，结论与必要证据进入 docs；正式发布后可删除合成素材与构建输出，发布目录和校验清单保持版本快照。

## 10. 文档与进度维护

每轮开始明确场景、范围、验收与不确定项；结束记录实际结果、未覆盖环境和剩余问题。区分“已实现”“已自动验证”“已实机验证”“已发布”，本地构建不等于完整验收。

涉及资料模型和数据库时先完成迁移、备份与兼容设计；涉及原生交互时保留真实 Windows 记录。

以原文件安全、标注可靠、查找效率和交接成功率评估进度。稳定版依据环境验收结果，浏览器与 Agent 的投入依据明确场景和试用反馈。
